# TinyCC for NuttX on the Epson C33

`tcc` compiles and runs C **on the device**, generating native Epson C33 PE
instructions, linking them against selected NuttX libc functions, and
executing them from RAM. It is a compiler, not an interpreter, and nothing
is compiled on the host at run time.

This directory is the NuttX side of the port: the NSH command, the runtime
the generated code links against, the headers and examples installed on the
target, and the application build. The compiler itself, including its C33
backend, lives in a separate TinyCC checkout; see `README.c33.md` there for
the backend, the ABI and the target's limits.

## Configuration

`CONFIG_INTERPRETERS_TCC` needs `ARCH_C33`, `BUILD_FLAT` and a non-zero
`LIBC_MAX_EXITFUNS`, and selects `LIBC_FLOATINGPOINT` and `FS_TMPFS`.

`CONFIG_INTERPRETERS_TCC_SRCDIR` locates the TinyCC checkout providing
`libtcc.c`, `tccgen.c` and the `c33-*.c` backend. A relative path resolves
from the apps directory, so the default `../tinycc` expects the checkout
beside `apps/` in the NuttX root. The build fails with a message naming the
path if nothing is there.

## Build and launch

From the NuttX root, for the WikiReader board:

```sh
export PATH="$PWD/.venv/bin:$HOME/wikireader/host-tools/toolchain-c33/work/install/bin:$PATH"
tools/configure.sh -e -m -a apps wikireader:tcc KCONFIG_OLDDEFCONFIG=olddefconfig
gmake -j8
"$HOME/wikireader/emulator/wremu" -g nuttx
```

The `wikireader:tcc` configuration extends the LCD/keyboard configuration
with TinyCC, tmpfs, 256-character shell lines and exit callbacks, and leaves
`wikireader:lcd` available for the smaller terminal image.

## Using it

The first invocation creates small C headers under `/tmp/tcc/include` and two
examples, without overwriting files that already exist:

```sh
tcc -run /tmp/hello.c
tcc -run /tmp/fib.c
echo '#include <stdio.h>' > /tmp/mine.c
echo 'int main(void) { puts("I compiled this here!"); return 0; }' >> /tmp/mine.c
tcc -run /tmp/mine.c
tcc -c /tmp/mine.c -o /tmp/mine.o
tcc -run /tmp/mine.o
```

`tcc -e 'int main(void) { return 0; }'` compiles a source string. Options
`-I`, `-D` and `-U` take an attached argument and precede `-run file.c`.
Arguments after the input are passed to the compiled program, including ones
beginning with a dash. `tcc -h` lists the supported command forms. The
command accepts one input file, either C source or an ELF object generated by
this backend. Saved objects are relocated again on each run, so their libc
addresses resolve against the running image.

## Self-hosting

The image carries the compiler sources, installed under `/tmp/tcc/src` on
first use. Build a compiler on the device, then use it:

```sh
tcc -selfhost
tcc -run /tmp/tcc.o -run /tmp/fib.c
```

Rebuild the compiler with the compiler just built:

```sh
tcc -run /tmp/tcc.o -c /tmp/tcc/src/bootstrap.c -o /tmp/tcc2.o
tcc -run /tmp/tcc2.o -c /tmp/tcc/src/bootstrap.c -o /tmp/tcc3.o
tcc -run /tmp/tcc3.o -run /tmp/hello.c
```

`bootstrap.c` includes the full TinyCC implementation and a small standalone
command driver, so the preprocessor, parser, code generator and linker in
each generation are compiled from those sources. The running image supplies
libc, the GCC arithmetic routines, setjmp/longjmp and task cleanup; the
generated compiler calls no compilation function in the initial one.

Later generations take longer because the C33 backend does not perform GCC's
optimizations. Sources can be edited in place with `vi` before rebuilding;
installation preserves files that already exist.

**Everything in `/tmp` disappears at reboot.** On the WikiReader there is no
SD-card driver yet, so persistent storage is a separate next step.

## How it is put together

`tcc_library.c` includes the TinyCC implementation from the configured source
directory, so the compiler builds as one translation unit inside the
application. `embed.py` generates `tcc_files.h`, which carries the target
headers, the examples and the compiler sources installed into tmpfs on first
use; the Makefile passes it the source directory. `tccdefs_.h` is generated by
building TinyCC's own `conftest.c` with the host compiler.

The private `compat/setjmp.h` uses GCC's builtins for compiler error recovery
in the initial compiler. Generated compilers and programs use the C33 assembly
implementation in `c33_setjmp.S`, exposed through the target `setjmp.h`.
Neither changes NuttX's public headers.

The runtime tracks generated compiler states and destroys them before freeing
the code implementing their cleanup callbacks. SIGINT is deferred during each
generation's compilation and cleanup, then enabled while its output program
runs. Exit and Ctrl-C unwind the whole chain of compiler objects.

The command uses a 64 KiB stack. The frontend is serialized because its parser
has global state. Compiled programs share NuttX's flat address space and carry
the usual responsibilities of native C code.

## Validation

The device tests live with the board, since they drive the emulator. From the
NuttX root, after building `wikireader:tcc`:

```sh
python3 boards/c33/s1c33e07/wikireader/tools/test_tinycc.py
python3 boards/c33/s1c33e07/wikireader/tools/test_selfhost.py
python3 tinycc/tests/c33/run-abi.py
```

The device test writes its C source through NSH into tmpfs, compiles and runs
it, saves and reloads it, and compares its integer checksum against a host C
compiler. It also checks diagnostics, return/exit failures, five repeated
compilations, and recovery after stopping a compiled infinite loop with
Ctrl-C. NSH maps a nonzero builtin exit code to shell status 1.

The self-host test builds three native compiler generations, compares the
second and third objects byte for byte on the device, and uses the result for
integer and floating-point regressions, saved-object execution, and recovery
after compilation errors and program exit. No host compiler produces those
compiler objects or the programs they compile. A separate scenario checks
Ctrl-C during a program compiled by the generated compiler, followed by a
successful compiler invocation.

`run-abi.py` is a compiler test and is described in `README.c33.md`.
